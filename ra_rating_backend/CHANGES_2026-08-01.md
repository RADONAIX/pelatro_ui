## 1. Activating a replacement now supersedes the old version

`app/modules/rules/lifecycle/service.py` — `activate()`

Activation promoted the incoming version to `ACTIVE` but left the version it
replaced `ACTIVE` too. Two live versions of one rule then existed, which the
database's one-live-version exclusion constraint forbids — so activation either
tripped the constraint or, where it slipped through, left rating traffic able to
resolve either version.

Before promoting, `activate()` now selects every *other* version of the same rule
still in `ACTIVE` or `PUBLISHED`, marks it `SUPERSEDED`, and records each in the
mirror queue. It then `flush()`es — the constraint is checked at that flush, so
the demotions must land before the promotion, not alongside it.

Only sibling versions of the same `rule_id` are touched; other rules in the same
activation batch are unaffected.

## 2. Logical rule status follows the current version

`app/modules/rules/ingest/writer.py` — `write()`

Re-importing an existing rule key updated the logical row's name, description and
owner, but only reset `status` when the rule had been `RETIRED`. So importing a
new draft over a live rule left the logical row reading `ACTIVE` while its current
version was a draft.

The logical row now always takes the incoming `status`. The `was_retired` flag is
gone. Live pricing is not interrupted: the previously-live version keeps `ACTIVE`
in its own immutable version row until change 1 supersedes it at activation time.

## 3. Mirror reader re-binds the tenant after commit

`app/modules/mirror/sync.py` — `push_rule_version()`

Canonical tables enforce tenant isolation through PostgreSQL RLS driven by a
transaction-local setting. The mirror queue drains *after* the request's primary
transaction commits, and that commit correctly clears the setting. The reader
therefore opened a fresh transaction with no tenant bound, RLS filtered out the
row it had just written, and the version was logged `mirror_version_missing` —
silently skipping the mirror rather than failing.

`push_rule_version()` now calls `tenant_context.bind_session()` with
`current_tenant()` before its first read.

## 4. Clone no longer stacks `(copy)` suffixes

`ra_demo/src/routes/rating/rules/$ruleId.tsx`

Cloning built the new name as `` `${rule.rule_name} (copy)` ``, so cloning a clone
produced `Tariff A (copy) (copy)`. A new `cloneRuleName()` helper strips any
trailing run of `(copy)` (case-insensitive, whitespace-tolerant) before appending
exactly one.

## Tests

Two tests added:

- `test_activating_a_new_version_supersedes_only_its_previous_version` — activates
  v1, imports v2, asserts v1 stays `ACTIVE` while v2 is a draft, then activates v2
  and asserts v1 is `SUPERSEDED` and v2 alone is `ACTIVE`.
- `test_canonical_mirror_reader_rebinds_tenant_after_primary_commit` — monkeypatches
  the tenancy context and asserts `push_rule_version()` binds the current tenant
  before reading.

### Verification status — read before applying

Run on this machine with `ra_rating_backend/venv`:

| Test | Result |
| --- | --- |
| `test_canonical_mirror_reader_rebinds_tenant_after_primary_commit` | **passes** |
| `test_activating_a_new_version_supersedes_only_its_previous_version` | **errors in fixture setup, unverified** |

The activation test never reaches its assertions. Fixture setup fails while seeding
`ra_rule.rule_stage`:

```
InsufficientPrivilegeError: new row violates row-level security policy
for table "rule_stage"
```

**This is pre-existing and not caused by these changes.** On the clean `454faf2`
baseline the same two files give **28 failed / 24 passed**; with these changes
applied, **29 failed / 25 passed** — the delta is exactly the one new passing test
and the one new test blocked by the same fixture fault. The local database role
lacks `BYPASSRLS` (or the fixture does not bind a tenant before seeding), which
takes out all 28 DB-backed tests in that file regardless of this work.

So change 1 — the most substantial of the four — is **untested end to end here**.
Please run the activation test in an environment with a correctly privileged test
database before relying on it.
